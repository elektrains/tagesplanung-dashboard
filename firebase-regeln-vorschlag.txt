Vorschlag für die Realtime-Database-Regeln
==========================================
Projekt: elektra-tagesplanung-23b62
Stand: 13.11.2026

WICHTIG ZUERST LESEN
--------------------
Ich konnte die aktuell gesetzten Regeln nicht auslesen — die Firebase-CLI gibt
sie nicht her. Das hier ist deshalb ein VORSCHLAG, kein fertiger Ersatz. Bitte
vorher in der Konsole die bestehenden Regeln ansehen und vergleichen:

  Firebase-Konsole → Realtime Database → Regeln

Geprüft habe ich nur eines: Lesen funktioniert heute ohne Anmeldung (die
Reading-App braucht das, sie hat keinen Login). Ob auch ohne Anmeldung
GESCHRIEBEN werden kann, habe ich bewusst nicht getestet — dafür hätte ich in
die produktive Datenbank schreiben müssen.


WAS DER VORSCHLAG BEWIRKT
-------------------------
1. Lesen bleibt für alle offen, sonst funktioniert die Reading-App nicht mehr.
2. Schreiben verlangt grundsätzlich eine richtige Anmeldung (Management-App).
3. Eine einzige Ausnahme: der Wandbildschirm darf bei einer Werkstatt-Aufgabe
   das Erledigt-Häkchen setzen und zurücknehmen — sonst nichts. Er kann weder
   den Tagesplan ändern noch Aufgaben anlegen, löschen oder umbenennen.
4. presence bleibt ohne Anmeldung schreibbar, weil die Reading-App dort
   einträgt, wer gerade online ist.


DIE REGELN
----------
{
  "rules": {
    // Lesen: offen, wie bisher. Die Reading-App und der Wandbildschirm
    // haben keinen Login.
    ".read": true,

    // Schreiben: nur mit echter Anmeldung, also aus der Management-App.
    // Anonyme Konten (der Wandbildschirm) kommen hier NICHT durch.
    ".write": "auth != null && auth.token.firebase.sign_in_provider != 'anonymous'",

    // Die Reading-App trägt ohne Anmeldung ein, wer gerade online ist.
    "presence": {
      ".write": true
    },

    "werkstattAufgaben": {
      "$aufgabe": {
        // Die einzige Stelle, an die der Wandbildschirm schreiben darf.
        "erledigt": {
          ".write": "auth != null",
          ".validate": "newData.isBoolean()"
        },
        "erledigtAm": {
          ".write": "auth != null",
          ".validate": "newData.isNumber() || newData.val() == null"
        }
      }
    }
  }
}


VORHER AKTIVIEREN
-----------------
Firebase-Konsole → Authentication → Sign-in method → Anonym → aktivieren.
Ohne das meldet der Wandbildschirm "Nur Ansicht" und das Abhaken ist gesperrt.
Der Plan wird trotzdem angezeigt.


RISIKO UND RÜCKWEG
------------------
Punkt 2 ist eine Verschärfung: heute kann möglicherweise jeder schreiben, der
die Adresse kennt. Danach nicht mehr. Das ist gewollt, kann aber etwas brechen,
das ich nicht kenne — die dritte App im Ordner "App" habe ich nicht geprüft.

Deshalb nach dem Speichern der Regeln einmal durchgehen:
  - Management-App: Baustelle verschieben, Status setzen → muss gehen
  - Reading-App: Plan ansehen → muss gehen
  - Wandbildschirm: Aufgabe abhaken und wieder zurücknehmen → muss gehen
  - App-Ordner (Monteur-App): einmal öffnen und bedienen

Falls etwas klemmt: in der Konsole unter Regeln gibt es eine Versionshistorie,
die vorherige Fassung lässt sich mit zwei Klicks zurückholen.
